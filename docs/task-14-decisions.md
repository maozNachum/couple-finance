## Minimal contract and evidence policy

Version 1 is a derived, memory-only result: explicit household/date/month/currency request, server snapshot timestamp, external coverage always UNKNOWN, module calculation states and deterministically ordered findings. Each finding has a stable root identity/type, household subject, immutable evidence references and versions, financial measurement dates separate from recording timestamps, original currencies, reason codes with fixed Hebrew explanations, affected result identities and supported navigation or an explicit limitation. Multiple result symptoms share one root finding; no lifecycle, dismissal store, score or canonical generated text.

Reuse existing reporting, budget, obligation and forecast calculations without changing formulas. A narrow additive STABLE SECURITY INVOKER RPC calls the existing obligations snapshot once and adds category/budget history under the same statement snapshot and RLS. No client-supplied SQL or identity, no new table or privileged helper. Retain existing graph/collection limits and enforce a combined 16 MiB limit. The Task 13 ledger authorization InitPlans remain unchanged. Complete graph validation precedes evaluation. A bounded finding result fails explicitly instead of silently truncating.

Observation age is exact Gregorian days from the selected measurement to the requested valuation date. Any carried observation is dated/partial under existing reporting policy, **not an invalid valuation, daily update obligation or source outage**. Measurement, recording and snapshot timestamps remain separate. LEDGER openings never come from observations. Historical FX uses existing exact-date/direction uniqueness semantics, never today's rate. Unknown external coverage remains separate even when known data have no findings or calculations are internally COMPLETE.

Forecast diagnostics are evaluated only for an explicit valid forecast request on the same household/date/currency and snapshot. Without explicit accessibility and buffer input, forecast is NOT_EVALUATED and links to its existing workflow; no invented zero buffer or account inclusion. Unmatched movements are not errors. Uncategorized recognized expenses differ from unknown financial effects; category findings apply only to affected category budgets.

Actions navigate only to existing module routes; they do not pass identity as authorization. Destination loaders independently reauthorize. Unsupported FX acquisition/source authority/settlement timing remain explicit limitations. Refresh, focus, visibility and Auth events discard protected snapshots and stale requests. Household switching discards previous derived findings/forecast choices, invalidates in-flight results and evaluates the selected household within the authorized graph. No persistent browser cache or automatic corrections.

## Final evidence and action mapping

Balance roots use account identity; historical FX roots use original/target currency and required date; classification/category roots use transaction identity; reconciliation roots use relationship identity; payment roots use occurrence identity. IDs include contract version, household and finding type. Multiple module impacts merge under these roots; current and originally selected immutable revisions are retained for stale evidence. Source authority activation is metadata, never substituted for measurement date.

Opening/effect problems link to transactions, observed balance problems to accounts, category problems to categories, relationship problems to reconciliation, and payment problems to obligations. Manual observations can carry FX in the existing accounts editor; there is no independent historical-FX editor or supported nonmanual source correction. Forecast limitations only link to forecast when its current controls can support review. Archived accounts and unsupported settlement/future-income assumptions retain explicit limitations. No route claims to automatically select or correct a particular record.

The combined snapshot limit is 16 MiB, with existing graph limits plus 10,000 categories/budget revisions. Findings fail explicitly beyond 2,000 roots or 10,000 evidence/impact references per root. UI pagination does not truncate the evaluated result. These limits avoid a generic pagination/synchronization protocol in this task.
