One optional TOTAL parent per household/month contains every allocation, including shared and member spending. It is a benchmark, never added to child plans. Child scopes are ALL (category required), SHARED (category optional), or MEMBER (durable member required; category optional). ALL means every ownership in one category; SHARED means only explicit HOUSEHOLD allocation ownership. MEMBER means only explicit allocation member attribution, never account-owner inference or percentages. Child scopes intersect if both category and ownership sets intersect; commands reject intersections atomically under a household lock. Distinct member scopes and shared scope are disjoint. Whole-owner and category plans for that owner cannot coexist. All active plans for one household/month use one selected supported currency; no cross-currency plan summation. Archiving releases the scope while retaining its identity/history. TOTAL and child plans remain independent benchmarks; no requirement that child planned amounts sum to TOTAL.

Budget identity, household, month, currency and scope are immutable. Edits change nonnegative planned Money only; archival appends a terminal revision, with no reactivation. Create uses expectedVersion 0; later commands require the current version. Every immutable revision retains durable actor, server UTC timestamp and category name/version snapshot. Category renames preserve IDs; current labels and historical plan labels are available. Archived EXPENSE categories may retain/edit/archive existing plans but cannot receive new plans. INCOME categories are ineligible. Historical revoked/unlinked members retain attribution; new member plans require active membership. A plan cannot supply ownership percentages: unsupported scopes fail validation.

Financial month is the canonical half-open date-only interval. Actuals reuse posted current EXPENSE lines and historical exact-recognition-day unique-direction FX, eight-place HALF_UP. Positive refunds reduce consumption. Other effects/openings/states are excluded by Task 10. All Task 10 monthly uncertainty conservatively propagates to every scope (including income FX issues), avoiding false green comparisons. Uncategorized EXPENSE stays in TOTAL/whole-owner actuals and has a separate breakdown; category plans are incomplete while eligible uncategorized expenses could belong to them. No guessing category names or effects. Unclassified and unresolved/stale/incorrect card reconciliation retain warnings and explicit correction links; no amount is suppressed.

COMPLETE means computation over registered canonical evidence, not certified external statements. No accounts, gaps or missing conversions never become verified zero. Partial actuals display only recognized converted expenses; none available means null. COMPLETE with no expense is known zero. Remaining=plan−actual, over=max(actual−plan,0), utilization=actual/plan×100 (two decimal HALF_UP; null for zero plan). These comparison metrics are null when incomplete or archived. A missing plan remains NO_PLAN, distinct from explicit zero and ARCHIVED. Unbudgeted amounts are expenses outside all active child scopes (TOTAL does not allocate them); missing FX or global uncertainty prevents a complete claim. Refunds may produce negative consumption/utilization. Remaining is not cash, forecast or safe-to-spend.

Persistence: unexposed finance budget heads and immutable revisions; restrictive composite household/member/category FKs; SELECT-only household RLS, private receipts/minimal audit. Invoker API wrappers call one narrow private plan command with live Auth user/session and active membership checks before receipt replay. Household lock serializes complete-payload idempotency, overlaps, currency and version checks. Atomic revisions/receipt/audit roll back on late failures. No financial tables are mutated. Core validates history continuity, immutable scope, actors, category references and complete graph.

A lost response retains the exact immutable command and key for retry; definitive conflicts require reload and a new explicit edit. Household/month changes reset drafts. No recurring engine, rollover, forecasting, production deployment or Task 12 implementation.
