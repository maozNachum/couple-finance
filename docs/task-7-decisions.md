# Task 7 decisions, before implementation

Baseline: PR #4 merged at `7f12a0d6d4c182a22bfe50fd56d3b41912e79968`; exact master push CI [38161119861](https://github.com/maozNachum/couple-finance/actions/runs/38161119861) completed successfully. Dedicated branch: `feature/task-7-csv-import-preview`.

Add private upload records with restrictive household/account/source/member references and a private immutable-object Storage bucket. Existing account/source identity and authority are unchanged. A selected MANUAL source is context only: it does not turn CSV evidence into MANUAL transaction provenance. Task 8 must explicitly resolve a FILE_IMPORT relationship before any commit; Task 7 does not create or activate sources.

Add a reviewed exact portable preview contract, distinct from canonical Transaction. Generic column positions/options are a public ingestion contract; actual CSV parsing and raw rows belong exclusively to the generic CSV provider adapter. An Edge Function parses downloaded bytes under the caller's JWT, with database-backed session/membership authorization before and after processing. No service-role credential is needed for processing. Preview rows remain in request/page memory only; no browser persistence and no database row payload growth. UI lifecycle includes processing/mapping/ready/failed; durable metadata records authorization/cancellation and expiration. Task 8 must reparse immutable bytes, never trust browser preview data.

Initial limits: 1 MiB UTF-8 bytes, 2,000 data rows, 32 columns, 2,048 UTF-16 units per cell, 160-character filename, 20 retained upload records per household until controlled cleanup. Header row required; duplicate/blank headers rejected. Comma/semicolon are explicit, never guessed. UTF-8 with optional BOM only; invalid UTF-8, XLS/XLSX and other encodings rejected. Date format, decimal/group separators, sign direction and currency selection are mandatory. ISO currencies must match the existing account; mixed currency rows are invalid. Excess Money precision fails without rounding. Unknown reporting effect remains UNCLASSIFIED.

Authorization lasts 24 hours; cancellation immediately blocks upload/read/process while retaining a deletion-only path. Storage deletion is explicit, retriable and audited; database metadata removal occurs only after object absence is verified by a narrow command. No automatic physical-deletion promise: a local operator cleanup command removes only expired/cancelled staging objects using Storage API, then removes staging metadata, retaining a minimal private audit. Production scheduling is deferred with deployment. The installed Storage operation helpers were verified before finalizing policies: authenticated GET/list and deletion have distinct allowlists; signing and signed uploads are denied. Signed URLs are deliberately unavailable because even a short-lived bearer URL could survive membership revocation until expiration. A future separately reviewed URL endpoint must bound TTL and document that limitation; authenticated downloads here recheck permissions each request.

No existing canonical contracts, merged migrations, ledger writes, categories or locks change. No new framework/dependency. Enable local Storage/Edge runtime and extend the existing verification chain for adapter, Storage, lifecycle and no-ledger-mutation tests.

Processing is limited to 100 database authorization checks per file (two for a successful inspection/preview; failures can consume one), and Edge I/O is aborted after 15 seconds. HTTP mapping input is at most 8 KiB. Preview UI renders 25 rows per page without dropping the remaining rows. Minimal audit records have a 30-day operator-cleanup retention.
