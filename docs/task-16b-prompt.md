# Proposed Task 16b — explicit historical FX evidence intake

Proposal only. Do not begin until Task 16a has independent review, merge and
successful exact-master post-merge CI, followed by explicit authorization.

Task 16a's synthetic savings measurement retained 250.75 USD, PARTIAL coverage
and missing historical USD/ILS evidence. Intake improved the original-currency
picture without claiming an ILS valuation. Existing observation forms accept a
manual rate on the measurement date; reporting and reconciliation consume
existing household-scoped immutable FX evidence. There is no independent
historical FX entry/selection workflow for arbitrary transaction recognition
dates. This is a concrete usability boundary, not evidence that a provider
integration is required.

First audit existing reusable FX identities, exact-date/direction selection,
ambiguity behavior, ownership, authority and correction history. Identify a
synthetic transaction with absent conversion evidence and demonstrate the
shortest currently supported safe resolution. Prefer explicit selection of
already retained eligible evidence before proposing any writer.

Present a minimal evidence contract and reviewable authorization/privacy
design before implementing a new endpoint or migration. A rate's origin,
effective date, recording date and immutable identity must remain separate
from the balance measurement, transaction recognition and requested reporting
dates. Do not overwrite old observation FX, infer inverse rates, choose a
current rate for history, or hide ambiguous evidence. Manual input remains a
user declaration, with no independent source-verification claim.

If a narrow manual historical-rate writer is justified, obtain explicit
approval for that schema/authorization change before implementation. Test
exact decimal precision, context/source mismatch, immutable ID reuse,
corrections, absent/competing rates, cross-household isolation, revocation,
uncertain delivery, and recalculation through existing canonical functions.

Deliver before/after synthetic evidence, mobile RTL accessibility, unchanged
full verify, exact-head standard CI and an independent-review package. No
financial engine rewrite, bank/card connections, FAIR/Harel APIs, live sync,
dynamic FX fetching, credentials, AI, persistent sessions, deployment or real
financial files. Any future provider choice needs verified data rights,
historical fixtures, provenance/revision policy and service access; none is
assumed available or a dependency of this proposed manual workflow.
